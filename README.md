# Spotter Freight-Rate ML Assessment

This repository contains an end-to-end, leakage-aware freight-rate modeling
workflow for the Spotter assessment. It audits the supplied data, evaluates
baseline and advanced models with chronological backtests, locks two models for
different prediction contracts, and creates scorer-ready outputs plus a
professional assessment report.

The employer-provided `readme.md` is intentionally unchanged. On
case-insensitive Windows filesystems, `README.md` would overwrite that file, so
candidate documentation is stored here as `CANDIDATE_README.md`.

## Final model decisions

- Main assessment submission: direct-target Ridge, `alpha=10`, using the full
  validation feature set. It won rolling mean MAE, worst-fold MAE, and temporal
  stability across July-October expanding-window validation.
- December chart: CatBoost with 100 iterations, depth 8, learning rate 0.10,
  L2 3, RMSE loss, seed 42, CPU. Its December-compatible feature policy uses
  pickup, delivery, distance, equipment, weight, and deterministic date/domain
  features. It does not use coordinates, `market_index`, `quote_signal`, or a
  route token.

The two-model design is deliberate: assessment validation provides signals
that are absent from the fixed December input contract.

## Repository structure

```text
src/                         Audit, features, evaluation, finalization, report code
tests/                       Fast framework and final-artifact contract tests
reports/                     Phase reports, results, metadata, figures, final report
outputs/                     Generated December prediction CSV
models/                      Serialized final models (gitignored binary artifacts)
scorer_results/              Chart generated by the unchanged employer scorer
validation_predictions.csv   Main submission file
```

## Setup

Python 3.11 is recommended.

```powershell
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
```

On macOS/Linux, replace `venv\Scripts\python.exe` with
`venv/bin/python` in the commands below.

## Reproduce the workflow

Run the data audit and experiments if a full reconstruction is desired:

```powershell
venv\Scripts\python.exe src\data_audit.py
venv\Scripts\python.exe src\evaluate_baselines.py
venv\Scripts\python.exe src\evaluate_advanced.py
```

Fit the locked models on all labeled rows and create final artifacts:

```powershell
venv\Scripts\python.exe src\finalize.py
```

Run all tests, including deterministic saved-model inference:

```powershell
venv\Scripts\python.exe -m unittest discover -s tests -v
```

Run the employer scorer unchanged:

```powershell
venv\Scripts\python.exe score.py --predictions validation_predictions.csv --december-predictions outputs\december_chart_predictions.csv --output-dir scorer_results
```

Build the PDF report after the scorer chart exists:

```powershell
venv\Scripts\python.exe src\build_report.py
```

## Key outputs

- `validation_predictions.csv`: exactly 12,000 unique template-aligned IDs and
  positive finite predictions.
- `outputs/december_chart_predictions.csv`: original seven-column December
  contract with 31 positive predictions.
- `models/final_ridge.joblib` and `models/final_december_catboost.cbm`: saved
  fitted models.
- `reports/final_model_metadata.json`: parameters, versions, ranges, hashes,
  and positive-floor diagnostics.
- `reports/final_prediction_summary.json`: overall and sliced sanity checks.
- `reports/final_assessment_report.md` and
  `reports/spotter_ml_assessment_report.pdf`: final narrative report.

## Reproducibility and source integrity

The seven employer-supplied files are treated as immutable. Their SHA-256
digests are recorded in `reports/source_file_hashes.sha256` and rechecked before
and after finalization. `load_id` and `posted_rate` are prohibited model
features. All model selection used chronological expanding windows; the hidden
assessment validation target was never available or used.

Generated model binaries are gitignored because they are reproducible and may
be platform/version sensitive. Commit source code, tests, reports, prediction
CSVs, metadata, and the scorer chart. Do not commit `venv/`, `tmp/`, caches, or
other environment artifacts.

## Limitations

The official hidden metric is unknown. Rare expensive loads remain compressed,
and the final set has greater unseen-city/route exposure than labeled temporal
folds. `market_index` is valuable in backtests but operationally uncertain. The
December year-end jump is a calendar extrapolation from a compact model, not a
causal forecast of a known market event.
